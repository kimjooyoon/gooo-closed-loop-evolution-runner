# Closed-loop evolution runner v1

The metacode at [`.gooo/closed-loop-evolution-runner.gooo`](../.gooo/closed-loop-evolution-runner.gooo)
is the only semantic authority. It declares the fixed eight-stage chain,
terminal reasons, next operations, capability vocabulary, UNKNOWN tuple,
precedence, denominator, and promotion boundary. Go parses that source,
lowers typed candidates into IR, executes the caller-owned temporary fixture,
and verifies exact evidence.

The eight stages are counterexample observation, immutable tool resolution,
typed rewrite, synthesis, temporary next generation, selection verification,
independent bootstrap, and replay/finalization. Every case records each
stage's input/output digest, capability, terminal reason, next operation,
wall_ms, and peak_rss_kib.

## Fixed vector

The denominator contains exactly five cases:

| Case | Expected | Witness |
| --- | --- | --- |
| `case-01-one-bug-repair` | `CLOSED` | the failing normalizer test passes after a generated Go rewrite |
| `case-02-ambiguous-candidates` | `UNKNOWN` | equal-priority typed candidates are not selected |
| `case-03-semantic-drift` | `REFUTED` | the generated lower-case rewrite fails the counterexample |
| `case-04-missing-immutable-tool` | `UNKNOWN` | a missing lock entry cannot be treated as a tool |
| `case-05-byte-identical-replay` | `CLOSED` | replay produces identical generated bytes and terminal witness |

Resolution is `REFUTED > UNKNOWN > CLOSED`. UNKNOWN always contains exactly
`stage`, `step`, `reason`, `unknown_class`, `next_operation`, and `blocked_by`.
UNKNOWN and REFUTED atomically deny artifact promotion.

The repair case retains the exact baseline failing test evidence, generated
semantic IR, generated `generated_normalization_fix.go`, evolved passing test,
and independent bootstrap passing test. Improvement is accepted only when
the same scenario, source, contract, toolchain, and runner digests bind an
exact before/after pair. No score, weighted average, or estimated percentage
is emitted.

## Immutable inputs and boundaries

The five existing component releases in
[`contracts/immutable-tool-lock-v1.json`](../contracts/immutable-tool-lock-v1.json)
are downloaded by CI and verified against the public Release API, annotated
tag object, release id, asset digest, and `immutable=true`. The runner reads
only those downloaded assets; it never reads a sibling checkout, branch, or CI
status. A missing release, missing asset, digest mismatch, or lock mismatch
remains UNKNOWN evidence.

The input repository is read-only. Temporary generations, semantic IR, and
reports are written only below the caller-owned output directory. The runner
has zero repository-write, commit, merge, or release authority. GitHub Actions
is the validation authority for Go 1.27 build, tests, conformance, integration,
and semantic audit.
